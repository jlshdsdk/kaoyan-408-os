5.4 本章疑难点

本章最后梳理两个容易混淆的疑难问题：一个是设备分配策略如何做到灵活、成功率高；另一个是用户缓冲区与内核缓冲区到底有什么区别、各自起什么作用。

疑难点一：如何改进设备分配策略，以提高其灵活性和成功率？

可以从以下两个方面对基本的设备分配程序加以改进。

1）增强设备无关性

进程使用逻辑设备名发起 I/O 请求。系统首先从系统设备表（SDT）中查找该类设备的第一个设备控制表（DCT）；若该设备正忙，则继续查找下一个 DCT；仅当所有同类设备均处于忙碌状态时，才把进程挂起，并将其加入该类设备的等待队列。反过来说，只要存在一个可用设备，系统就进入后续的安全性检查与分配流程，不会让进程白等。

2）支持多通路 I/O 结构

为避免 I/O 瓶颈，现代系统常采用多通路设计：一台设备可以连接多个控制器，一个控制器也可以连接多个通道。在这种结构下，控制器与通道的分配同样要逐级尝试：若设备所连接的第一个控制器（或该控制器所连接的第一个通道）正忙，就尝试下一个；仅当所有相关控制器（或通道）均不可用时，分配才宣告失败，进程被挂入相应的等待队列；只要有一个可用，即可完成分配。

在具有通道的系统中，设备分配需要依次访问 SDT → DCT → COCT → CHCT。成功分配一个设备必须同时满足：设备可用、控制器可用、通道可用。因此常称——「设备分配，要过三关」。

考点两条改进策略（增强设备无关性、多通路 I/O）与「三关」是本章收尾的常考内容：分配时要逐层查找、逐级尝试，只有全部同类设备（或全部相关控制器、通道）都忙才挂起进程，只要有一个空闲就继续分配流程。数据结构的访问顺序 SDT→DCT→COCT→CHCT 要能默写，并对应「设备—控制器—通道」三级层次。

疑难点二：用户缓冲区与内核缓冲区的定义及作用分别是什么？

用户缓冲区

用户进程在读取文件时，通常会预先申请一块内存区域（如一个数组），称为缓冲区（Buffer），用于暂存从文件中读取的数据。每次调用 read 系统调用时，操作系统把读取的数据填充到该缓冲区中，应用程序便可直接从中获取数据；其中的数据处理完毕后，再发起下一次 read 系统调用重新填充缓冲区。

用户缓冲区的主要作用是减少系统调用的次数，进而降低因频繁在用户态与内核态之间切换所带来的开销。

内核缓冲区

内核缓冲区是操作系统在内核空间中维护的缓冲区。它对读、写两个方向的工作方式不同：

  • 读方向：用户进程请求读取磁盘数据时，系统并不直接访问磁盘，而是先检查内核缓冲区中是否已缓存所需数据——若存在，直接把数据从内核缓冲区复制到用户缓冲区；若不存在，内核才发起磁盘 I/O 请求，并把当前进程挂起、转而调度其他进程执行；磁盘数据被读入内核缓冲区后，再复制到用户缓冲区，并唤醒该进程。
  • 写方向：用户进程提交的数据通常不会立即写入磁盘，而是先写入内核缓冲区；当缓冲区中的数据积累到一定量，或满足特定刷新条件时，内核才把数据批量写入磁盘。

内核缓冲区的核心目的是提升磁盘 I/O 的整体效率，尤其对写操作具有突出的优化效果。

两者对比

维度用户缓冲区内核缓冲区
位置用户进程自行申请的用户空间内存（如数组）操作系统在内核空间中维护
管理者应用程序自己填充与消费操作系统统一管理，对用户透明
主要作用减少系统调用次数，降低用户态/内核态切换开销缓存磁盘数据、合并延迟写入，减少直接磁盘 I/O 的次数
对读操作承接每次 read 填入的数据命中则直接复制给用户，未命中才发起磁盘 I/O
对写操作—（写路径中暂存待发送的数据）数据先入内核缓冲区，积累到一定量或满足刷新条件才批量落盘
提示内核缓冲区「写操作先缓冲、满足条件再批量落盘」的做法，与 5.3.3 节「提高磁盘 I/O 速度的方法」中的延迟写是同一思想：合并多次写操作、减少 I/O 次数。分清记忆：用户缓冲区省的是系统调用与态切换的开销，内核缓冲区省的是磁盘 I/O 的开销。
