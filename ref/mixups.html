第1章 操作系统概念、运行环境与结构

并发 vs 并行（1.1.3）

并发并行
发生时刻同一时间间隔内同一时刻
微观实质交替执行、分时占用 CPU多个事件真正同时进行
硬件条件单处理机即可（配合中断与调度）需要多核 CPU / 多处理机
典型例子单处理机上的多道程序（宏观并行、微观串行）CPU 与 I/O 设备之间、多个 I/O 设备之间

共享的两种方式：互斥共享 vs 同时访问（1.1.3）

互斥共享方式同时访问方式
访问限制一段时间内仅允许一个进程访问允许多个进程在宏观上「同时」访问
微观实质一个进程用完并释放后，另一进程才能用通常是分时交替访问（分时共享）
典型资源打印机等独占设备；栈、变量、表格等临界资源磁盘上的只读文件、可重入（纯）代码

中断（外中断）vs 异常（内中断）（1.3.3）

中断（外中断）异常（内中断）
来源CPU 执行指令外部的事件CPU 执行指令内部的事件
典型例子I/O 结束中断、时钟中断非法操作码、地址越界、运算溢出、缺页、陷入指令
分类可屏蔽中断（INTR）、不可屏蔽中断（NMI，如掉电）故障（缺页、除零）、自陷（系统调用）、终止（硬件故障）
可否屏蔽分可屏蔽与不可屏蔽一旦发生必须立即处理，不可屏蔽
处理后返回返回第 i+1 条指令通常返回第 i 条重新执行（如缺页）

系统调用 vs 库函数（1.1.2 / 1.3.4）

系统调用库函数
身份操作系统提供给应用程序的唯一程序接口，每个系统调用有唯一调用号语言标准库提供的函数，不是操作系统接口
运行状态经陷入指令进入内核态，由内核服务程序执行在用户态运行；仅当封装了系统调用时才陷入内核
关系库函数是对系统调用的封装：printf() 最终经 write 输出、malloc() 可能调 brk/mmap；而 strlen()、sqrt() 等纯计算型库函数完全在用户空间运行，不涉及系统调用

内核态 vs 用户态（1.3.2）

内核态（管态）用户态（目态）
可执行指令完整指令集（特权指令＋非特权指令）仅非特权指令；执行特权指令触发异常并被终止
地址空间可访问全部地址空间内存访问被限制在用户地址空间
典型操作启动外设、设置时钟、关闭中断、修改模式位一般计算和数据处理
切换用户态→内核态的唯一途径是中断或异常（系统调用、外中断、异常、试图执行特权指令）；内核态→用户态由内核执行返回指令（如 IRET）完成

宏内核 vs 微内核（1.4）

宏内核（单内核/大内核）微内核
内核构成主要功能模块集成在一个紧密耦合的整体中、运行于内核态仅保留最基本功能（进程调度、进程间通信等），遵循「机制与策略分离」
非核心功能文件系统、驱动等也在内核态移到用户态服务器进程，经消息传递交互（客户/服务器模式）
性能高（免切换与消息传递开销）短板（频繁穿越内核态/用户态）
可靠性等文件系统崩溃会拖垮整个系统单个服务崩溃可重启恢复；扩展性、安全性、可移植性好
代表Linux、Windows（宏内核或混合内核）Fuchsia、HarmonyOS NEXT

第一类 vs 第二类虚拟机管理程序（1.6）

第一类虚拟机管理程序第二类虚拟机管理程序
别名裸金属架构寄居架构
运行位置直接运行在物理硬件之上以应用程序形式运行在宿主操作系统之上
特权地位系统中唯一处于最高特权级的软件本质是用户态进程
角色类似一个轻量级的操作系统向客户操作系统伪装成完整硬件平台
代表——VMware Workstation（x86 平台首个广泛使用者）
速记并发＝同一时间间隔，并行＝同一时刻，并发与共享互为存在条件；用户态进内核态的唯一途径是中断/异常；访管（陷入）指令在用户态执行、不是特权指令，系统调用服务程序才在内核态执行。

第2章 进程与线程、CPU 调度、同步互斥与死锁

进程 vs 程序（2.5）

维度进程程序
动态 vs 静态程序及数据的一次执行活动，有生命周期有序指令的集合，静态存放于外存
暂时 vs 永久暂时存在（创建—运行—消亡）可长期保存，永久存在
能否派生能通过创建原语创建新进程本身无法生成新进程
组成程序段＋数据段＋PCB（PCB 是进程存在的唯一标志）仅一组有序指令

进程 vs 线程（2.1.7）

维度进程线程
基本单位资源分配的基本单位CPU 调度和执行的基本单位（「轻量级进程」）
拥有资源拥有独立地址空间与资源不拥有系统资源，仅有 TCB、寄存器、栈等私有数据结构；同进程线程共享代码段、数据段、堆、文件描述符
切换开销切换涉及整个地址空间，开销大同一进程内线程切换不引起进程切换，开销小；跨进程的线程切换才会引起进程切换
并发与多核进程间可并发并发性更强；多线程可同时调度到多个 CPU 并行

用户级线程 vs 内核级线程（2.1.7）

维度用户级线程（ULT）内核级线程（KLT）
管理者用户空间的线程库，内核感知不到，调度仍以进程为单位操作系统内核，为每个 KLT 维护 TCB，直接以线程为调度单位
切换开销在用户空间完成，无须进内核态，开销小需陷入内核态，开销大
阻塞影响一个线程执行阻塞型系统调用，整个进程被挂起仅该线程阻塞，同进程其他线程仍可被调度
多核并行无法并行（内核只能看到进程）可同时调度到多个 CPU 并行

五种状态的主动 / 被动转换（2.1.4）

转换触发条件性质
创建 → 就绪PCB 填写完成、资源到位，插入就绪队列系统完成创建
就绪 → 运行被调度程序选中获得 CPU被动（被调度）
运行 → 就绪时间片用完；或抢占式系统中被更高优先级进程剥夺 CPU被动（被剥夺）
运行 → 阻塞系统调用请求的服务需等待事件（如发起 I/O）主动
阻塞 → 就绪所等待事件发生（如 I/O 完成），由中断处理程序唤醒被动
运行 → 终止正常结束或异常/外界干预—

不存在的边：阻塞态不能直接进入运行态（唤醒后只能回就绪队列重新排队）；「就绪→阻塞」也不存在——阻塞操作只能由运行态进程发起。

CPU 调度算法全家（2.2.5）

算法能否抢占优点缺点
FCFS 先来先服务否公平、实现简单不利于短作业；有利于 CPU 繁忙型、不利于 I/O 繁忙型；不适合分时/实时
SJF/SPF 短作业优先非抢占（抢占版＝最短剩余时间优先 SRTN）所有作业同时到达且运行时间已知时，平均等待、平均周转时间最优长作业饥饿；估计时间难定；未考虑紧迫程度
HRRN 高响应比优先否兼顾长短作业，长作业不会饥饿每次调度都要计算响应比，开销大
优先级调度分非抢占式与抢占式两种灵活反映紧迫程度，配合抢占可满足实时要求静态优先级下低优先级进程可能饥饿
RR 时间片轮转可以（时钟中断剥夺）公平、响应快，适合分时系统平均等待时间长、切换开销大；时间片过大退化为 FCFS、过小切换频繁
多级反馈队列队列之间可抢占（新进程入 1 级队列立即抢占低级队列进程，被抢占者回原队列末尾）「相当通用」；无须预知运行时间，长作业不会饥饿最复杂

会饥饿的算法：SJF（长作业）、静态优先级（低优先级）；不会饥饿：FCFS、HRRN、RR、多级反馈队列。

死锁 vs 饥饿 vs 死循环（2.4.1）

维度死锁饥饿死循环
产生原因竞争不可剥夺资源＋推进顺序非法，形成循环等待链分配策略不公平，等待时间无上界（如 SPF 中长作业被无限推迟）程序自身逻辑错误，与资源分配策略无关
涉及进程数≥2 且相互构成循环等待可以只有一个进程只涉及该进程自身
进程状态必定全部处于阻塞态可能就绪（分不到 CPU）也可能阻塞（等 I/O）处于运行态，并未阻塞
系统表现卷入进程全部卡死，无外力干预永不推进系统整体正常运行，个别进程被「饿着」其余部分照常运行，该进程空转

死锁的四个必要条件（2.4.1）

条件含义对应预防措施
互斥资源一段时间内只能被一个进程占有一般无法破坏（互斥是正确性前提）
不可剥夺已获资源使用完前不能被强行夺走申请新资源得不到满足就释放已有全部资源
请求并保持持有资源又申请新资源，阻塞时不放手一次性申请全部资源（静态分配）
循环等待存在进程环，每个都在等下一个占有的资源资源有序分配（按编号递增申请）

四个条件须同时满足才会死锁，破坏其一即可预防；只有每类资源仅一个实例时，「资源分配图有环」才是死锁的充要条件，多实例时有环未必死锁。

死锁预防 vs 避免 vs 检测解除（2.4.1–2.4.4）

策略思路代价
预防事先立规矩，破坏四个必要条件之一（一次性分配 / 剥夺 / 有序分配）实现简单，但限制严格、资源利用率低
避免每次分配前动态判断是否仍处于安全状态（银行家算法：合法性→可用性→试探分配→安全性检查，不安全就回滚）限制较宽松、利用率较高，但须预知最大需求且每次分配都要算
检测＋解除不限制申请，定期用资源分配图化简检测，发现后资源剥夺 / 撤销进程 / 进程回退最宽松，但有检测与解除的开销，终止进程会丢失已完成的工作

安全状态三句话：安全状态一定不会死锁；死锁时系统必定处于不安全状态；不安全状态未必演变为死锁。

同步 vs 互斥（2.3.1 / 2.5）

对比项互斥（间接制约）同步（直接制约）
制约来源相互竞争临界资源相互协作完成同一任务
表现形式一个进程使用临界资源时其他进程必须等待在关键点等待对方发出的信号，协调执行次序
典型例子多进程争用一台打印机单缓冲系统中输入进程与计算进程「先写后读」
信号量初值互斥信号量固定为 1由具体情况确定：消息未产生为 0，已存在为相应非负整数

联系：两者都源于并发进程对资源的共享与相互依赖；广义上互斥可视为一种特殊的同步。

信号量 vs 管程（2.3.4 / 2.3.6）

维度信号量机制管程机制
形态整型变量 value＋等待队列，只能经 P/wait、V/signal 原语访问名称＋共享数据结构＋一组过程＋初始化语句（与类 class 高度相似）
互斥的实现P(S)、V(S) 由程序员自行夹紧临界区自动保证任一时刻仅一个进程在管程内执行，无须显式编写互斥代码
「值」的有无有整数值：>0 为可用资源数，<0 时其绝对值为等待进程数条件变量没有值，仅用于排队和通知；资源数由共享变量（如 S）显式记录
使用方式分散在各进程中，顺序不当易死锁（如两个 P 操作顺序颠倒）由进程被动调用管程过程；既能实现互斥又能实现同步
速记进程是资源分配的基本单位、线程是调度的基本单位；运行→阻塞是主动行为，阻塞→就绪是被动行为，阻塞态永远不能直接进运行态；交换两个同步 P 操作的顺序可能死锁，交换两个 V 操作的顺序没有任何问题。

第3章 内存管理

静态重定位 vs 动态重定位（3.1.1）

维度静态重定位（可重定位装入）动态重定位（动态运行时装入）
转换时机装入时一次性把所有逻辑地址改为物理地址装入后不转换，推迟到指令真正执行时进行
实现依赖装入程序直接修改地址重定位寄存器存起始地址，物理地址＝逻辑地址＋重定位寄存器值
能否移动装入后不能移动，也不能运行中动态申请内存支持程序移动，便于紧凑，减少外部碎片
硬件代价无须额外硬件需要重定位寄存器（特权指令装入）

内部碎片 vs 外部碎片（3.1.2）

内部碎片外部碎片
定义分配给进程的分区（页框）内部未被利用的空间分区（段）之间难以利用的小空闲块——总量够用但不连续
产生方式单一连续分配、固定分区；分页的页内碎片（每进程平均约半页）动态分区分配；分段（段间空隙）
对策权衡页面/分区大小紧凑（拼凑），前提是系统支持动态重定位

四种动态分区分配算法（3.1.2）

算法空闲链排列 / 查找优点缺点
首次适应按地址递增，从链首找第一个够用的保留高地址大空闲区；回收无须重排，综合性能最优低地址端易积累小碎片
邻近适应同按地址递增，从上次结束位置继续循环查找查找分布更均匀大空闲区被逐渐切分，整体性能通常不如首次适应
最佳适应按容量递增，取第一个能满足的（最小可用）尽量保留大空闲区每次留下极小剩余块，产生大量外部碎片，性能通常很差
最坏适应按容量递减，取最大的切分剩下的碎片通常仍可用，减少小碎片大分区很快耗尽，难以满足大作业

分页 vs 分段 vs 段页式（3.1.3–3.1.5、3.3）

维度分页分段段页式
出发点系统管理需要，提高内存利用率，对用户透明用户需要：方便编程、共享与保护、动态增长、动态链接先按用户视角分段、再在段内按系统视角分页
单位大小页固定（2 的整数次幂，硬件划分）段不固定（编译程序按逻辑划分）段不固定，段内页固定
地址空间一维（一个线性地址即可定位）二维（须给段号＋段内偏移）二维（对用户仍是段号＋段内地址）
碎片无外部碎片，有页内碎片无内部碎片，有外部碎片段内再分固定大小的页，内存仍以页框为单位分配；兼有两者的表结构开销（每进程一张段表＋每段一张页表）
共享与保护可以共享但以页为单位，繁琐以段为单位，方便自然（每进程一个段表项即可）以段为单位共享保护
无快表访存次数2 次（查页表＋取数据）2 次（查段表＋取数据）3 次（查段表＋查页表＋取数据）

快表命中 vs 未命中（3.1.3）

步骤快表命中快表未命中
查 TLB并行比较命中，直接得块号 b（不访存）无匹配页号
查慢表（内存中的页表）不需要需要，取出块号 b（第 1 次访存）
访问目标数据第 1 次访存第 2 次访存
合计1 次2 次（并把该项调入快表，满则按置换算法淘汰）

快表有效依赖局部性原理：局部性良好时命中率可达 90% 以上，分页引入的性能开销可控制在 10% 以内。

缺页中断 vs 一般中断（3.2.2 / 1.3.3）

缺页中断一般（外）中断
归属内中断（异常中的「故障」）外中断
产生时机在指令执行期间产生并立即处理指令执行结束后检测中断请求信号再响应
一条指令内次数可能多次：copy A to B 若指令与两操作数各自跨页，最多 6 次每个事件对应一次中断
处理后走向重新执行引发缺页的那条指令返回第 i+1 条指令继续执行

OPT / FIFO / LRU / CLOCK 页面置换算法（3.2.4）

算法淘汰依据性能开销与要点
OPT 最佳置换以后永不使用、或最长时间内不再被访问的页理论缺页率最低无法实现（要预知未来），仅作评价标杆
FIFO 先进先出最早进入内存的页（队首）忽略局部性，性能通常较差实现最简单；唯一可能出现 Belady 异常的算法
LRU 最近最久未使用最近最长时间未使用的页（看过去）性能接近 OPT需硬件记录各页上次访问以来的时间，实现开销大；永远不会有 Belady 异常
CLOCK（NRU）循环扫描访问位：为 1 先置 0 再下移（给一次机会），为 0 淘汰以较小开销逼近 LRU缺页才移动指针，命中不动；指针停在被替换帧的下一帧；改进型再引入修改位，优先淘汰 (A=0, M=0)

同一访问序列、3 个物理块下的缺页次数：OPT 9 次、FIFO 15 次；LRU 依据「过去」、OPT 依据「未来」，LRU 前 5 次缺页与 OPT 相同只是巧合。

Belady 异常（3.2.4）

内容
定义分配的物理块数增加，缺页次数反而上升的反直觉现象
根源FIFO 只依据调入时间决策，完全忽略页面实际使用情况
教材例访问序列 3,2,1,0,3,2,4,3,2,1,0,4：3 个物理块缺页 9 次，4 个物理块反而 10 次
判定只有 FIFO 可能出现；OPT 和 LRU 永远不会

抖动 vs 工作集（3.2.5）

抖动（颠簸）工作集
是什么刚换出的页面马上又要换入、刚换入的又立刻被换出的频繁调度某段时间间隔内进程实际访问页面的集合 \(W(t,\Delta)\)，Δ 为工作集窗口尺寸
根源 / 关系分配的物理块（驻留集）太少，无法满足进程正常运行的基本需求，CPU 利用率急剧下降驻留集大小不应小于工作集大小，否则进程将频繁缺页
对策按缺页率或工作集动态调整页框数，必要时挂起（换出）部分进程对局部性好的程序，工作集大小一般远小于 Δ
速记页为系统、段为用户；页定长、段变长；页一维、段二维；页内碎片、段外碎片。问「缺页中断次数」是 9，问「置换次数」是 6——扣不扣初始装入的 3 次是最大陷阱；多级页表省的是连续内存，并不会加快地址变换。

第4章 文件管理

逻辑结构 vs 物理结构（4.1.3）

逻辑结构物理结构（存储结构）
视角用户视角看到的文件组织形式文件在外存上的实际存储方式
范畴无结构（流式）文件；有结构（记录式）文件的顺序、索引、索引顺序、散列组织连续分配、链接分配（隐式/显式 FAT）、索引分配
透明性用户可见对用户透明
关系逻辑结构说明「是什么」、物理结构说明「怎么存」，二者没有直接制约关系；但物理结构选择不当就难以体现逻辑结构的特点（如顺序逻辑文件配隐式链接物理结构便无法快速定位）

四种文件物理分配：连续 / 隐式链接 / 显式 FAT / 索引（4.2.6、4.4）

方式访问第 n 条记录访盘次数优点缺点
连续分配1 次（起始块号＋记录长度直接换算）顺序存取快；支持随机（直接）访问要求连续空间，有外部碎片；须预知长度、不利于动态扩充
隐式链接n 次（从链头逐块跟指针）无外部碎片、利用率高；动态增长方便只能顺序访问；任一指针坏则链断，可靠性差；指针占空间
显式链接（FAT）实际 1 次（FAT 常驻内存，内存查链不占访盘）支持直接访问；查找在内存完成、磁盘 I/O 少；FAT 中 -2 表项还能兼任空闲空间管理FAT 需常驻内存，磁盘越大表越大，内存开销显著
索引分配单级 2 次；m 级索引 m+1 次支持随机访问；易于增删；无外部碎片每个文件都要索引块，小文件浪费；多级索引读盘次数增多

单级 / 两级 / 树形 / 无环图目录（4.2.3）

结构组织优点缺点
单级目录全系统一张线性目录表实现简单，能按名存取查找慢、不允许重名、难共享
两级目录主文件目录 MFD＋各用户的用户文件目录 UFD解决不同用户间的重名，检索快用户内部无法再分类
树形目录根目录＋多层子目录（主流结构）便于分类、层次清晰、便于管理保护；设置当前目录可加快检索按路径逐级访问中间目录，磁盘 I/O 较多
无环图目录树形＋指向同一节点的共享边支持文件/子目录跨目录共享须维护共享计数器，计数归零才能真删，管理开销增加

硬链接 vs 软链接（4.2.8）

比较项硬链接（基于索引节点）软链接（符号链）
实现多个目录项指向同一个索引节点，链接计数 count 记录链接数新建 LINK 类型文件，内容只有被共享文件的路径名
访问速度经目录项指针直达索引节点，快先读符号链再按路径逐级查目录，可能多次读盘，慢
拥有者删除后仅删其目录项、count 减 1；count>0 文件仍在，他人可继续用文件被真正删除，他人访问失败（不悬空），可安全删除符号链
空间开销索引节点多一个计数字段，很小符号链是独立文件，占索引节点和磁盘空间
适用范围依赖索引节点，限同一文件系统内记录网络地址＋路径名可实现网络文件共享

位示图 vs 成组链接（4.3.2）

位示图法成组链接法（UNIX）
思想一个二进制位对应一个盘块：0 空闲、1 已分配空闲盘块分组（每组 100 块），每组的第一个盘块作索引块记录下一组，链接成链；第一组信息装入内存空闲盘块号栈
分配扫描找 0 位 → 换算盘块号 \(b=n(i-1)+j\) → 置 1从栈顶取号；分到栈底号时先读入该块中的下一组信息，再分配该块
回收按 DIV/MOD 公式换算行列号 → 置 0压入栈顶；栈满（100 项）时把整栈写入新回收的盘块作新索引块，栈中只留该块号
适用结构紧凑、可常驻内存；位图大小随磁盘容量增大，适合中小规模兼顾可扩展性与性能，适合大型文件系统

另有空闲表法（连续分配，配合首次/最佳适应）与空闲盘块链 / 空闲盘区链（离散分配）：盘块链单块操作简单但链长，盘区链效率高、链短但回收要合并。

速记访问第 n 条记录的访盘次数：连续 1 次、链接 n 次、m 级索引 m+1 次；FAT 常驻内存后查链不占访盘、实际 1 次。open 只把目录项/索引节点（控制信息）读入内存而非文件内容，之后一切操作凭文件描述符，不再用文件名。

第5章 输入/输出管理

四种 I/O 控制方式（5.1.2）

对比项程序直接控制（轮询）中断驱动DMA通道
CPU 干预频率全程：发命令后不断循环测试状态每个字（节）就绪中断一次仅每块数据的开始（预处理）和结束（后处理）只发一条 I/O 指令，整组完成或出错才中断
传送单位字（节）字（节）数据块一批数据块（一组通道指令）
数据流向设备→控制器→CPU 寄存器→内存（必经 CPU）设备↔内存直接传送，不经 CPU；通道还能管理多台设备
缺点CPU 与设备串行、利用率极低按字节中断、块设备场景低效参数仍需 CPU 预置；一台控制器通常只服务一台设备需专用硬件，成本高

演进主线：每种新方式都是为了克服前一种的主要缺点——问「CPU 干预程度最低」答通道，四选项无通道时答 DMA。

缓冲区 vs 高速缓存（5.2.2）

缓冲区（Buffer）高速缓存（Cache，如磁盘高速缓存）
存放内容正在传输过程中的数据已存在于慢速设备上的数据副本
存活时间传输完成通常立即释放可长期驻留直至被替换
目的缓和速度差、减少中断频率、匹配数据粒度、提高并行性提高重复访问的效率（命中则免访问低速设备，减少磁盘 I/O 次数）

相同点：都位于高速设备与低速设备之间，都为缓解速度差异。

单缓冲 vs 双缓冲（5.2.2）

单缓冲双缓冲（缓冲对换）
每块平均耗时\(\max(T,C)+M\)\(\max(T,\;C+M)\)
并行关系设备写入 T 与 CPU 处理上一块的 C 并行；M 永远串行；缓冲区是临界资源须互斥访问设备写入 T 与「传送＋处理另一块」的 C+M 并行
例（2011 统考）10 块、T=100、M=50、C=50（μs）：第 1 块 200，其余每块增量 150，共 1550μs每块 100μs 连续读入，最后一块再 M+C 收尾，共 1100μs

双机全双工通信时，每台机器须分设发送缓冲区＋接收缓冲区；循环缓冲与缓冲池只考机制、不考定量计算。

设备分配的数据结构：DCT / COCT / CHCT / SDT（5.2.3）

表数量记录内容
设备控制表 DCT每台物理设备一张设备类型、标识符、状态（忙/闲）、指向 COCT 的指针、重复执行次数、设备队列队首指针
控制器控制表 COCT每个控制器一张控制器状态、连接的通道表指针、控制器等待队列
通道控制表 CHCT每个通道一张通道状态、连接的控制器表首址、通道等待队列
系统设备表 SDT全系统一张设备类型、标识符、DCT、驱动程序入口——设备分配的查找起点

分配按 SDT → DCT → COCT → CHCT 逐级查找，设备、控制器、通道三者都可用才算成功（「过三关」）；逻辑设备名→物理设备名由逻辑设备表 LUT 在设备独立性软件层完成映射。

SPOOLing（假脱机）技术（5.2.4）

内容
组成输入井/输出井（磁盘）＋输入/输出缓冲区（内存）＋输入/输出进程（模拟外围机）＋井管理程序
数据流向输入：输入设备→输入缓冲区→输入井→用户进程；输出：用户进程→输出井→输出缓冲区→输出设备
本质用磁盘井＋软件模拟脱机外围机，把一台独占设备虚拟为多台逻辑共享设备，以空间换时间
常考结论需要大容量外存与多道程序技术支持，不需要外围计算机；设备与井之间的传送由系统（输入/输出进程）完成；用户进程实际分到的是外存区（虚拟设备）而非物理设备

六种磁盘调度算法（5.3.3）

算法核心规则（方向约束）优点缺点
FCFS按请求到达先后服务，方向无约束公平、简单平均寻道距离大，仅适用于 I/O 较少场合
SSTF每次选距当前磁头最近的请求，方向由「最近」决定性能优于 FCFS不保证平均寻道最短，可能饥饿
SCAN必须扫到磁盘端点才能折返（电梯调度）寻道性能较好、避免饥饿对远离磁头一端的请求响应较慢
C-SCAN单向扫描服务，回程快速跳转不服务（回扫距离计入总数）消除对两端磁道请求的不公平—
LOOKSCAN 改进：到当前方向最远请求处即折返，无须抵达端点省去到端点的空跑仍双向扫描
C-LOOKC-SCAN 改进：单向服务到最远请求处即快速回返单向公平＋更少空跑—

同一请求队列（55,58,39,18,90,160,150,38,184，磁头在 100、向磁道号增大方向）的总移动道数：FCFS 498、SSTF 248、SCAN 282、C-SCAN 390、LOOK 250、C-LOOK 322。

机械磁盘 vs 固态硬盘 SSD（5.3.4）

机械磁盘固态硬盘（SSD）
结构磁性盘片＋磁头，有寻道与旋转延迟等机械延迟闪存芯片＋闪存翻译层（替代磁盘控制器），无机械部件
随机访问慢（寻道时间占主导）随机读/写延迟极低，性能明显优于机械盘
读写/擦除单位以扇区（块）为单位读写读/写以页为单位（512B～4KB），擦除以块为单位；随机写慢：擦除慢一个数量级＋改页前要先把块内有效页搬走
寿命无擦写次数限制问题每块擦写寿命有限（几百至几千次），易磨损→动态磨损均衡（写入时选低擦写块）＋静态磨损均衡（空闲时迁移冷数据）延长寿命
调度磁盘调度算法优化寻道无寻道，FCFS 即可；划分扇区、降低寻道时间只与机械盘有关，磨损均衡是 SSD 特有
速记CPU 干预最少的是通道（选项无通道时选 DMA）；寻道时间占主导，磁盘调度的目标就是减少平均寻道时间，旋转延迟与调度算法无关；可能饥饿的是 SSTF——CLOCK 是页面置换算法，不是磁盘调度。
